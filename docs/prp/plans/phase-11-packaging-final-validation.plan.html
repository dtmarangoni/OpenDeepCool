Approach
  • The package: one PKGBUILD in packaging/arch/, plus an .install file and three pacman hooks (owner, 2026-10-26; solution review OV-02):
    • the units are enabled by symlinks the package ships under /usr/lib/systemd/, which pacman installs and removes;
    • systemd's own pacman hooks create the account and reload systemd, udev and D-Bus;
    • then the package's post-transaction hook starts the service on install, or restarts it on upgrade; a pre-transaction hook stops it before removal;
    • post_install only removes a dev copy (from its manifest) and prints the message;
    • post_remove deletes the account, the state directories, and what the detection's root-only record says it created.
  • The test: a small Rust program, odc-pkg-test. It builds a throwaway Arch root rootless, with pacstrap -N and arch-chroot -N (unshare mode as a regular user), so no password prompt ever interrupts a run. It then:
    • snapshots the root;
    • installs both ways (AUR-style and GitHub-style);
    • uninstalls;
    • compares the root with the snapshot.

Nothing is booted (owner, 2026-10-25: no boot testing). - Release: 1. tag v1.0.0; 2. the PKGBUILD's source is that tag's GitHub archive with its checksum; 3. the AUR repository is pushed under the project's no-reply identity; 4. the owner's PC moves to the package; 5. the full parity run; 6. DeepCreative's deletion, from a list the owner confirms.

Acceptance

AC1 — Installs from the AUR and from GitHub: both ways build the same package and install every file of FILES.md with its owner and mode; the service is enabled by the package's symlinks and started by its install hook on a real system, after systemd's hooks; the audio helper is enabled for all users; the message says how to turn them off (Tasks 2, 3, 5, 6).
AC2 — Uninstall leaves nothing: after install and uninstall, both ways, the throwaway root equals its snapshot except the listed, commented exceptions; an upgrade keeps the account and settings; the lm-sensors configuration is removed only when OpenDeepCool's detection created it, according to its root-only record, whose fields are yes/no facts; a forged record removes nothing (Task 3).
AC3 — The dev copy disappears: installing the package removes every path of the dev manifest, in the container and on the owner's PC, and keeps the owner's settings (Tasks 3, 5).
AC4 — Packaging rules: nothing in /usr/local or /etc; namcap reports no errors; .SRCINFO is current; the AUR repository holds no binaries and no personal identity (Tasks 1, 2, 6).
AC5 — Parity at 100 %: the full unattended run passes against the installed package; every checklist row is proven or replaced by a recorded owner decision; the runtime drop-in is gone afterwards (Task 7).
AC6 — v1 released: v1.0.0 tagged and pushed, the AUR package published, both ways tested against the published sources (Task 6).
AC7 — DeepCreative gone: after the owner confirms the list, no DeepCreative material is left on the owner's PC, and the expected frames are still reproducible from committed tools (Task 8).
AC8 — Records: README install, uninstall and footprint sections, FILES.md, the PRD footprint and table, AGENTS.md Commands, and the Phase 11 report match what was built (Tasks 1, 4, 8).
