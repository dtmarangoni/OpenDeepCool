Approach
  • The package: one PKGBUILD in packaging/arch/, plus an .install file and three pacman hooks (owner, 2026-10-26; solution review OV-02):
    • the units are enabled by symlinks the package ships under /usr/lib/systemd/, which pacman installs and removes;
    • systemd's own pacman hooks create the account and reload systemd, udev and D-Bus;
    • then the package's post-transaction hook starts the service on install, or restarts it and the users' audio helpers on upgrade; a pre-transaction hook stops them before removal;
    • post_install only removes a dev copy (from its manifest) and prints the message;
    • post_remove deletes what the detection's root-only record says it created, the state directories, then the account.
  • The test: a small Rust program, odc-pkg-test. It builds a throwaway Arch root rootless, with pacstrap -N and arch-chroot -N (unshare mode as a regular user), so no password prompt ever interrupts a run. It then:
    1. snapshots the root;
    2. installs both ways (AUR-style and GitHub-style);
    3. uninstalls;
    4. compares the root with the snapshot. Nothing is booted (owner, 2026-10-25: no boot testing).
  • On the owner's PC:
    1. the package, built from the committed release candidate, replaces the dev copy;
    2. the owner's test access comes back, with one approved step (owner, 2026-10-27);
    3. a real upgrade restarts the service and the owner's audio helper;
    4. the full parity run, against the installed package.
  • The releases (alpha, beta, v1.0.0, the AUR repository) and DeepCreative's deletion belong to Phase 12 (owner, 2026-10-27).

Acceptance

AC1 — Installs both ways: the AUR way (from a local copy of the files the AUR will hold) and the GitHub way build the same package and install every file of FILES.md with its owner and mode; the service is enabled by the package's symlinks and started by its install hook on a real system, after systemd's hooks; the audio helper is enabled for all users; the message says how to turn them off (Tasks 2, 3, 5).

AC2 — Uninstall leaves nothing: after install and uninstall, both ways, the throwaway root equals its snapshot except the listed, commented exceptions; an upgrade keeps the enable links, the account, the detection record and the settings; the lm-sensors configuration is removed only when OpenDeepCool's detection created it, according to its root-only record, whose fields are yes/no facts; a forged record removes nothing (Task 3).

AC3 — The dev copy disappears: installing the package removes every path of the dev manifest, in the container and on the owner's PC, and keeps the owner's settings (Tasks 3, 5).

AC4 — Packaging rules: nothing in /usr/local or /etc; namcap reports no errors; .SRCINFO is current; the files for the AUR hold no binaries and no personal identity (Tasks 1, 2).

AC5 — Parity at 100 %: the full unattended run passes against the installed package; every checklist row is proven by a test, replaced by a recorded owner decision, or the cooler's own behaviour (its OpenDeepCool column); the runtime drop-in is gone afterwards (Task 7).

AC6 — Test access and a real upgrade: after the package replaces the dev copy, the owner's test access is back, recorded in the dev manifest, and a real upgrade restarts the service and the owner's audio helper on the new binary (Task 5).

AC7 — Only committed code is built: the PKGBUILD builds a published tag the same way both ways, a release candidate only from the committed HEAD, and a tree with uncommitted changes is refused (Tasks 2, 3).

AC8 — Records: README install, uninstall and footprint sections, FILES.md, the PRD footprint and table, AGENTS.md Commands, and the Phase 11 report match what was built (Tasks 1, 4, 8).
