Approach

Reuse the Phase 1 research rig as it is. Add two controlled inputs: chosen sensor values, injected where DeepCreative's main process receives its readings, and test tones played through PipeWire. Analyse old and new captures with the existing decoders. Use static analysis only where running the app can't answer. Write one spec document per concern; the owner checks each one and it's committed on its own.

Acceptance

AC1 — Protocol: docs/spec/protocol.md specifies every message DeepCreative 1.2.14 sent in any capture (format, checksum, frame bit layout, start-up command, timing), what it sends at start-up and exit, and what the display does when frames stop. Declared reports other than output report 16 are listed as never sent.

AC2 — Display: from docs/spec/display.md alone, every captured frame of modes 1–12 and Creative Mode can be drawn pixel for pixel, for every case of the test matrix: each mode in all four rotations, in both °C and °F where it shows a temperature, scrolling included (Task 4's render check).

AC3 — Music: docs/spec/music.md specifies modes 13–22: the audio source; the spectrum's layout; each emoji animation's frames and timing; and the value area. The Music Mode render check passes for every case of the test matrix.

AC4 — Sensors: docs/spec/sensors.md defines each metric DeepCreative shows (meaning, unit, rounding, refresh) and the Linux source the display service can read on any PC (owner, 2026-10-23: sensors work on any PC, read by a system service). The owner's devices and fan mapping are only in docs/local/machine.md.

AC5 — Settings: docs/spec/settings.md lists every LP-page and global setting that affects the cooler, with its values, default and what's restored at start-up.

AC6 — Parity checklist: docs/spec/parity-checklist.md covers every item of AC1–AC5, each linked to its spec section and evidence and checked by the owner on the cooler, and the owner has signed it off.

AC7 — Safety and privacy: during Phase 3 only DeepCreative, in its network-blocked prefix, sent messages to the LP360. Every system change was temporary and is listed in the PRD footprint. The commit guard passed on every commit.

AC8 — Records: the PRD's open questions are answered or marked after v1, its capabilities match the spec with the owner's OK, and the README and AGENTS.md reflect Phase 3's outputs.

AC9 — Expected frames: docs/spec/frames/ holds the expected frame of every test-matrix case, generated from the spec's rules and matching DeepCreative's captures. The Rust tests use it from Phase 5 on.
