# Parity checklist

One row for each mode, option, setting and behaviour in the spec. Each row links to its spec section, says what evidence backs it, and records the owner's check. Evidence labels are defined in [README.md](README.md). Phase 3 ends when the owner signs off the whole list ([sign-off](#sign-off)); Phase 11 runs it again against OpenDeepCool.

- **Mode:** DeepCreative's mode number, or `-` when the row isn't about one mode.
- **Owner check:** `ok <date>`, with what the cooler showed, or `pending`. A row about something the cooler can't show (bytes on the wire, sensor files) is checked by the owner reviewing its evidence: `reviewed <date>`.
- **OpenDeepCool** (owner, 2026-10-27): how OpenDeepCool meets the row, for the Phase 11 run.
  - `test: …`: the tests that prove it, each a link to its file (Phase 11, Task 9). A Rust test (`crates/odc-testkit/tests/parity_checklist.rs`) checks that every link names a function in its file and that every row has a valid kind.
  - `test: …; ours: …`: a test proves the row's mode or feature, but part of the row is DeepCreative's rule; OpenDeepCool's is in the rows named.
  - `replaced: …`: the row is DeepCreative's behaviour only; OpenDeepCool's rule is in the rows or section named.
  - `device`: the cooler's own behaviour, seen by the owner in Phase 3; it can't be tested unattended.
  - D36, D37, D42 and D43 apply to every row that draws a value: values in full up to 9999, static or scrolling by the value, exact whole-number arithmetic, the nearest whole number.
  - The checklist is at 100 % when every `test` row passes and every row it points to passes.
- Where DeepCreative does something OpenDeepCool deliberately doesn't, the row or its OpenDeepCool column says so; the owner checks DeepCreative's behaviour, and the spec section describes ours.
